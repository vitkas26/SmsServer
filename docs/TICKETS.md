# SmsServer — задачи

## SMS-01 — Воспроизводимая сборка

**Готово.** Обновлены Gradle, Android Gradle Plugin, Kotlin и зависимости; удалены динамические версии `+` и дубли. Старые ZIP-архивы в корне не участвуют в сборке. Целевая сборка — SDK 36, Java 17.

## SMS-02 — Реальный запуск и остановка сервера

**Готово.** Экземпляр Ktor хранится отдельно и останавливается через `stop()`. Исправлено зависание запуска из-за привязки серверных корутин к `withContext` экрана. Состояние кнопки меняется только после результата операции.

## SMS-03 — Доступ к сетевым командам

**Готово.** Сервер слушает только `127.0.0.1`; команды требуют случайный ключ в Bearer-заголовке. Номер и текст проходят проверку до отправки. Удалены жёстко прописанные номера и SIM-карты.

## SMS-04 — SMS и журнал

**Готово.** Входящие читаются с проверкой разрешения, закрытием курсора и сортировкой по дате. Журнал исходящих хранится в прежней Room-схеме `log.db`, запросы Room выполняются вне главного потока. Видимый список подключён к данным; даты считаются по локальному календарю, включая конец месяца.

## SMS-05 — Проверки

**Готово.** Unit-тесты проверяют ключ, номер и текст. UI-тест проверяет стартовый экран. На эмуляторе проверены HTTP health, отказ без ключа, чтение с ключом, отклонение неправильных команд, запуск и остановка сервера. Искусственное входящее SMS показано в списке без реальной сети. Отправка SMS и звонок не выполнялись.

## SMS-06 — Надёжная фоновая работа

**Ожидает требований.** Если сервер должен работать после закрытия экрана, перенести его в foreground service с уведомлением и подходящим типом службы. Добавить сценарии восстановления после остановки процесса Android.

## SMS-07 — Доступ по сети

**Ожидает требований.** Если шлюз нужен другим устройствам в Wi-Fi, предусмотреть защищённое соединение и явное включение доступа по LAN. Текущий loopback-режим доступен через `adb forward`.

## SMS-08 — Подтверждение доставки

**Ожидает требований.** Добавить статусы отправки и доставки через корректно зарегистрированные `PendingIntent`/`BroadcastReceiver` и хранить их в журнале. Сейчас `202` означает только постановку в очередь Android.
